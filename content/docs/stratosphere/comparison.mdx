Stratosphere is a fork of Pterodactyl, and so are Pelican and Hydrodactyl (formerly Pyrodactyl). All four run every
game server in its own Docker container through a daemon called Wings, and all of them speak the same client and
application APIs, so the base feature set is nearly identical. What separates them is what was built on top of it.

## What every fork inherits

Everything below is part of the base and works the same way in all four: Docker-isolated servers with CPU, memory,
disk and IO limits, Wings on every node, eggs and nests, allocations and ports, startup variables, subusers with
granular permissions, backups, databases, schedules, the file manager and console, SFTP, the activity log, and the
client, application and admin APIs. If a row below is about Minecraft, assume it is *not* in the base.

## What each one is for

**Pterodactyl** is the right answer if you want the upstream project, the biggest ecosystem of eggs, and support from
the largest community. It is general purpose: nothing about it is Minecraft specific, so every feature in the first
table is something you would add with an egg, a plugin or a script.

**Pelican** is the right answer if your servers are not all Minecraft. It modernizes the panel — plugins and themes
from a hub, admin roles, passkeys, webhooks, 32 languages, a health page — and it runs the same eggs and Wings
daemons in the same Docker containers.

**Hydrodactyl** is the right answer if what you care about is a small, fast frontend and a quick start: Vite and
Turbo builds, an installer for Minecraft content backed by Modrinth, Hangar and Spiget, S3 backups and PostgreSQL
support. It is the project this documentation site used to document.

**Stratosphere** is the answer if what you run is Minecraft, and you want the panel itself to do the work a
Minecraft host normally charges plugins for: installing software and mods, editing properties and inventories,
letting players join through a domain, sleeping idle servers, bursting past CPU limits and letting users create
their own servers. It stays a Pterodactyl underneath, so eggs, backups, databases, schedules, subusers and the API
behave exactly the way your team already knows.

## Also worth knowing

- **Closed-source panels** built on the same base exist (for example WISP). They are not free software, so they are
  not covered here.
- **Paid Pterodactyl plugins** cover a lot of the same ground as Stratosphere's built-in tools — a marketplace
  installer, custom domains, sleep, server creation. Stratosphere ships that functionality instead of selling it.
- **Pterodactyl 2.0** is in open beta and adds an extension SDK with a marketplace. Stratosphere is based on the
  stable 1.x line, and its extension system follows the same idea as the older Blueprint extension format: add pages,
  hooks and routes without touching the panel's own files.
- **Blueprint framework extensions** are not supported on Hydrodactyl, per its README.
