---
title: CPU Burst
description: Let a server spend saved-up CPU on short spikes above its limit.
---

A server has a CPU limit, say 200%. With **CPU burst**, a server that stays under its limit saves up the CPU it did not use and can spend it on a short spike *above* the limit, so a tick spike or a chunk generation does not lag. It never raises the limit for good.

This is the CFS burst of the Linux kernel (`cpu.max.burst`, Linux 5.14 or newer). Wings sets it on the container when the server starts.

## The admin setting

Under **Admin > Nodes > (a node) > Settings > CPU Burst** an admin sets it on or off and how much to save up, as a share of the limit. The share goes from **1 to 100**, which is also the most the kernel allows. It is on at **100%** by default, which is what Wings always did.

The panel sends the setting to Wings together with the other node settings, as the `docker.cpu_burst` part of the node configuration (also in the config of a node made with `wings configure`). It applies to a server the next time it starts, and turning it off clears it on the next start too.

A Wings that does not read it, or a node with `ignore_panel_config_updates: true`, keeps what its own `config.yml` says under `docker.cpu_burst`.

## The console indicator

Players and owners see a bolt next to **CPU Usage** on the console page.

- **Grey**: burst is ready.
- **Green**: the server is bursting now. Hovering says for how long ("CPU burst active for 12s") and, when it is not bursting, how high it can go and when it last did.

A server without a CPU limit, or on a node with burst off, has no bolt.

## How it is detected

Wings sends the burst counters of the kernel (`cpu.stat`: `nr_bursts`, `burst_usec`) with the stats, as `cpu_burst`. The server is bursting while the counter grows, and a burst counts as over after 3 quiet seconds.

Without the counter, such as an older Wings or a host where the cgroup cannot be read, the bolt guesses from the usage being above the limit.

The time is counted by the page, so a page opened in the middle of a burst starts counting when it opens.

## Short by design

A burst is short by design: the kernel allows at most as much saved CPU as the limit, so a spike lasts a moment and then the server is back at its limit.
