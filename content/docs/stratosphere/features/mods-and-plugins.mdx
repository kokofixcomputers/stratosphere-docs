The server's content page is where you browse and install add-ons. Three sources are available: **Modrinth**, **Hangar**, and, when it is set up, **CurseForge**. The switch at the top of the sidebar chooses the source.

## Modrinth

From Modrinth you can browse and install:

- mods,
- plugins,
- data packs,
- resource packs,
- worlds,
- and modpacks.

A project page shows its description, screenshots and versions with changelogs. Install puts the file in the right place on the server for you.

## Hangar

[Hangar](https://hangar.papermc.io) is the plugin repository of PaperMC. It has **plugins** for Paper (and what is built on it), Velocity and Waterfall, and nothing else, so the other kinds are not offered while Hangar is chosen. It needs no key and no setup: the browser asks `https://hangar.papermc.io/api/v1` directly, like it asks Modrinth, so nothing goes through the panel and nothing is stored.

Everything the content page does works with it: searching (words, category, Minecraft version, platform, sorting by popularity, downloads, stars, recently updated and newest), the page of a plugin, versions with changelogs, installing, dependencies that are on Hangar, installed plugins, updates and uninstalling. Ids from Hangar look like `hg:ViaVersion` (a version: `hg:ViaVersion@5.12.0`), so they never get mixed up with ids of other sites.

- **Hosted elsewhere.** A plugin author may keep the file on GitHub and only list the version on Hangar (EssentialsX does). Those versions show a **Download page** link instead of an Install button, like CurseForge files that may not be shared.
- **Snapshot builds.** Many plugins publish every build in a Snapshot channel. What is installed or offered as an update is the newest **release**. A snapshot is only installed when you choose that version on the Versions tab.
- **Which servers a plugin fits.** A plugin for Hangar's Paper platform is offered to Paper, Purpur, Folia, Spigot and Bukkit servers. Velocity plugins go to Velocity, Waterfall plugins to Waterfall and BungeeCord.
- **One category at a time.** Hangar filters on a single category.
- **No file hashes.** Hangar cannot say which project a jar belongs to from the file alone, so jars put on a server by hand are not recognised as Hangar plugins. Plugins installed through the panel are, because they are written down in `stratosphere.json`.

## CurseForge

With an API key from [console.curseforge.com](https://console.curseforge.com/), every server's content page gets a **CurseForge** tab next to Modrinth. It offers mods, plugins, data packs, resource packs and worlds, with descriptions, screenshots, versions and changelogs, and CurseForge's own categories, loaders and Minecraft versions. It also gives the mods in the file manager their icons.

An admin sets the key in **Admin > Settings > CurseForge**, as described on the [settings page](/docs/stratosphere/admin/settings). The panel checks the key with CurseForge right away and there is a button to check it again. The key is stored encrypted in the settings table and is never sent to a browser. Without a key, nothing about CurseForge appears. A key in the environment (`CURSEFORGE_API_KEY`) is used when no key was saved.

<Callout type="info" title="CurseForge ids">
Ids from CurseForge start with `cf:` (`cf:394468`) so they never mix with Modrinth ids, in the address, in the records of installed projects (`stratosphere.json`) and in the dependency planner.
</Callout>

## Installing and detecting files

- **Dependencies** are installed like on Modrinth: what a file lists as required (relation type 3) is offered with it.
- **Authors can keep their files off other sites.** Those files have no download address and show a link to CurseForge instead of an install button.
- **Detect existing** on the installed tab, and the icons in the file manager, recognise files by fingerprint: MurmurHash2, seed 1, over the bytes of the file without the tab, line feeds and space. It is computed in the browser. Modrinth is asked first, and CurseForge only about what Modrinth does not know.

## Worlds and modpacks

- **Worlds** are downloaded and unpacked into their own folder next to the others, the same as a world from a link. The archive has to be a `.zip` or `.tar.gz` and the **server has to be stopped**.
- **Modpacks** are installed from Modrinth only. CurseForge modpacks use a different format with a list of files to fetch, so they are not installed from there.

## Limits

A search shows at most **10,000 results**, which is as far as CurseForge answers.

## How CurseForge works inside the panel

CurseForge does not let a browser ask it things, and the key has to stay secret, so the browser asks the panel (`/api/client/curseforge/...`) and the panel asks CurseForge. Only a fixed set of reads is possible and every parameter is checked. Answers are cached for a few minutes (lists of categories and versions for six hours), so many people looking at the same mod use up one request of the key. Nothing is ever written at CurseForge. In the interface, `resources/scripts/lib/curseforge.ts` turns what CurseForge sends into the shapes the pages already use for Modrinth, and the address says which site is shown (`?s=curseforge`).

Every download is handled as a background **job** on the node, so you can leave the page while it runs. See [Jobs](/docs/stratosphere/features/jobs).
