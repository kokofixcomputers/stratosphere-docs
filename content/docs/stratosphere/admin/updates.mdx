## Admin > Updates

**Admin > Updates** is for **root admins only**. It can update the panel itself, the `mc-router` and `panel-edge` binaries (it restarts their services), the updater, and the Wings software of your nodes. Node updates are described in [Nodes](/docs/stratosphere/getting-started/nodes); the command-line update path is in [Updating](/docs/stratosphere/getting-started/updating).

## Update the panel

**Update the panel** downloads `panel.tar.gz` (latest release or nightly, your choice) and does what `tools/update-panel.sh` does, as root:

1. Backs up the current files to `/var/backups/stratosphere` (the last three are kept).
2. `php artisan down`.
3. Extracts the archive over the panel and `chown`s the files to the web user.
4. `composer install --no-dev --optimize-autoloader`.
5. `php artisan migrate --force`.
6. `php artisan db:seed`.
7. Clears the caches and restarts the queue worker (`pteroq`, or `QUEUE_SERVICE` in the env file).
8. `php artisan up`.

Then it updates the router and edge from the same archive, and the updater itself.

- If extracting or composer fails, the old files are put back.
- A failed migration leaves the new files in place, and the result says so.
- The panel always comes out of maintenance mode.
- The page shows the maintenance screen for a minute or two and picks up the result by itself.

The download is `PANEL_TAR_URL` (the latest release) or, with **Nightly** chosen, `PANEL_TAR_NIGHTLY_URL` (`.../releases/download/nightly/panel.tar.gz`). If a new build does not stay up, the previous one is put back and the result says so.

## Update router and edge only

**Update router and edge only** does the same download, but takes only the two binaries out of the archive.

**Update from the files on this machine** uses `tools/mc-router/dist` and `tools/panel-edge/dist` of the panel, so it uses what you extracted last.

## Setup, once

```bash
sudo bash tools/updater/install.sh
```

The panel's web user cannot restart services, so this installs a small root service (`stratosphere-updater.path`) that waits for the panel to write a request file, `storage/app/updates/request`, with one of these words:

```text
local, download, download-nightly, panel, panel-nightly, backups,
restore:NAME, delete-backup:NAME
```

`NAME` must look like `panel-backup-YYYY-MM-DD-HHMM.tar.gz`, optionally with `-before`. The panel and the updater both refuse anything else, so it can never be a path. Nothing else the panel writes is used: the download address and the paths come from `/etc/stratosphere-updater.env`, which only root can change.

Because the web user owns the panel files, a hacked panel could replace the binaries in `tools/*/dist` and have root run them. For that reason the files on this machine are only used when they do not belong to the web user. Run this once after extracting the panel:

```bash
sudo chown -R root: tools/mc-router/dist tools/panel-edge/dist
```

The download does not have this limit, because it comes from the release and not from a folder the panel can write to. `ALLOW_WEB_OWNED=1` in `/etc/stratosphere-updater.env` turns the check off.

## Progress and status

The result is written to `storage/app/updates/status.json` and shown on the page. While it works, the status says which step it is at (`download`, `backup`, `install`, `migrate`, `finish`, `tools`), and the progress bar of the page follows it. While the panel is in maintenance mode the page cannot ask, so it shows "restarting" and carries on when the panel is back.

## Backups

Every panel update first saves the panel files to `/var/backups/stratosphere` (the last three are kept). The **Backups** box on the Updates page lists them and can **restore** one or **delete** it.

- A restore first saves the current files as `panel-backup-...-before.tar.gz` (never pruned by a restore), puts the chosen files back, runs composer, clears the caches and restarts the queue worker.
- **The database is not rolled back**: a backup from before a migration may not work with the newer database.
- The updater writes `storage/app/updates/backups.json`, because that folder is root's.
