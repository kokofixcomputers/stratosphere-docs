---
title: Tunnels
description: Let servers be played from the internet without port forwarding, through ngrok, Pinggy, playit.gg or your own QuickExpose relay.
---

Servers can be played from the internet without forwarding a port on the router. **Admin > Settings > Tunnels** turns it on and picks the service, and the owner of a server opens one of its ports with one click on the **Network** tab.

## Choose a service

| Service | How the node does it | Token | Notes |
|---|---|---|---|
| **ngrok** | The ngrok agent built into Wings | Authtoken (required) | TCP tunnels need an account with a verified payment method. A free account lets one agent be online at a time, so give each node its own token. |
| **Pinggy** | An SSH connection made by Wings (`<token>+tcp@a.pinggy.io`). The host key of the first connection is kept in `<root_directory>/.tunnels` and has to stay the same | Pinggy token (optional) | Check what your Pinggy plan allows for TCP tunnels. |
| **QuickExpose** | Wings registers a name with a QuickExpose relay that you run and carries the players it sends | None. The **backend URL** is the address of your relay: `qe.example.com`, or `host:control:tunnel:play` for ports other than 7000, 7001 and 25565. There is no default, you have to give it | Players use `<name>.<your domain>:25565`. The relay does not pass the real IP of players on, so the server sees the node. |
| **playit.gg** | Wings makes a `minecraft-java` tunnel on your account through the API of playit.gg, and runs `playitd --secret <key>` while a tunnel is open | Agent secret key (required) | Install the `playit` package (it has `playitd`) on every node. |

Changing the service closes every tunnel and opens them again through the new one.

## Set it up

1. Make an account with the service (see the table for what it needs).
2. Under **Admin > Settings > Tunnels**, choose the service, enter its token (or the backend URL for QuickExpose), switch **Let people open tunnels** on and save. Tokens are stored encrypted and never shown again.
3. The nodes need the Stratosphere Wings of this release. The ngrok agent and the Pinggy client are built into it, so nothing else is installed (except `playitd` for playit.gg). A node that is too old marks the tunnel as failed ("can not be reached, or is too old to open tunnels").

With several nodes, a node can have a token of its own on the same page (*Tokens of nodes*). A node without one uses the token of the panel.

## What people see

- **Network tab.** Each port has a bar with **Open to the internet**. The node opens the tunnel in a few seconds and the bar shows the address players connect to, such as `0.tcp.eu.ngrok.io:12345`, with copy on click and **Close**. A failed tunnel shows why and can be tried again.
- **Connection menu.** The address is also in the connection menu of the server, next to the domains, and works in the server list of Minecraft.
- **Follows the server.** A tunnel is open while its server is running. It closes when the server stops and opens again when it starts (the node looks every few seconds). While the server is off the bar says the tunnel opens when the server starts. On free plans the address can be a new one every time, and the new one shows up by itself.
- **Limits.** A server can have 1 tunnel open at once by default (*Tunnels for each server*). Closing a tunnel, removing the port from the server or deleting the server closes it on the node. Opening and closing are in the activity log of the server.

## How it works

The panel keeps what is wanted (the `tunnels` table: server, allocation, status, address). The node asks `GET /api/remote/tunnels` for the service, the token and the ports of its servers that have a tunnel, opens them, and answers `POST /api/remote/tunnels/{id}` with `active` and the address, `waiting`, or `failed` and why.

When something changes the panel tells the node (`POST /api/tunnels/sync`). The node also asks when it starts and every three minutes, which opens a tunnel that failed or went away. Every few seconds it looks at which servers run and opens or closes the tunnels of the ones that started or stopped.

## Limits

- Minecraft Java (TCP) is what is tunnelled. Bedrock (UDP) and voice chat plugins that need UDP are not, with any of the services.
- Players connect through the service, so there is a little extra delay, and the bandwidth and terms of your plan apply.
- A tunnel that the service closes by itself (for example a free plan with a time limit) is reopened at the next sync, within about three minutes, usually with a new address.

<Callout type="warn">
  Tested with fakes: a fake node for the panel, and a fake ngrok, a fake Pinggy (an SSH server), a fake playit.gg API and a fake QuickExpose relay for Wings. QuickExpose was also tried by hand against the real relay program. Not tried against ngrok, Pinggy or playit.gg themselves.
</Callout>
