---
title: Trash
description: Keep deleted server files and schedules for a set number of days.
---

## Turning it on

The trash bin is **off by default**. Turn it on under **Admin > Settings > Trash** and choose how many days things are kept (**30 by default**). The server-side view is described in [Files](/docs/stratosphere/features/files).

With it on, what people delete from a server is kept in the trash bin of that server instead of being gone.

## What is kept

- **Files and folders** deleted in the file manager, and by the Content, Worlds and other pages that delete on behalf of the user. They are moved to a hidden folder, `.stratosphere-trash`, in the root of the server on the node: nothing is copied and nothing leaves the disk. The file manager never shows that folder and refuses to touch it.
- **Schedules** (with their tasks). They are hidden and stop running while they are in the trash bin.

## What is not kept

Because these cannot be put back, they are not kept:

- databases
- backups
- whole servers
- anything deleted over SFTP or from the console

## Per-server permissions

Per server, with subuser permissions (owners and anybody who may open every server have all of them):

| Permission | Allows |
| --- | --- |
| `trash.read` | See the trash bin (the Trash page on the server's menu, shown while the trash bin is on). |
| `trash.restore` | Recover things. Also needs the permission to make that kind of thing: `file.create` for files, `schedule.create` for schedules. |
| `trash.delete` | Delete things from the trash bin for good, empty it, and delete files without moving them to it. |

Admins use roles to decide who may change the trash bin settings: `settings.trash.view` and `settings.trash.update`.

## Disk quota and restoring

- Files in the trash bin **count toward the disk limit** of the server until they are recovered, deleted or expire.
- Recovering puts a file back where it was. If something is there now, it gets " (restored)" added to its name, nothing is overwritten, and a folder that is gone is made again.

## The hourly purge

Every hour the panel (`p:trash:purge`, scheduled by the usual cron) deletes what has been in there for longer than it is kept. A node that is down leaves it for the next time.

Turning the trash bin off does **not** empty it: what is in there stays until it expires. Changing the number of days applies to what is deleted from then on.

## Servers and the activity log

Deleting a server removes its trash bin records with it. The activity log records `server:trash.restore`, `server:trash.delete` and `server:trash.empty`; `server:file.delete` says whether the file was trashed.
