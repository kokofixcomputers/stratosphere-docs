title: stratosphere-net (router and edge)
description: The one Go program that gives servers custom domains (the router) and serves the panel over HTTPS (the edge).
---

`stratosphere-net` is one small Go program with two parts that can be switched on and off: the **router**, which gives Minecraft servers custom domains, and the **edge**, which serves the panel over HTTPS. They share one binary, one service (`stratosphere-net`), one settings file (`/etc/stratosphere-net.env`), one installer and one update step. Older installs that run `mc-router` and `panel-edge` as two services are moved over automatically, see [Moving an older install](#moving-an-older-install).

## The router

A player types `play.example.com` (the default port), the router reads the address from the first packet of the connection and forwards the player to the matching server allocation. The domain owner only needs an **A record** pointing at the machine the router runs on.

```text
player ── play.example.com:25565 ──▶ router ──▶ node-ip:allocation-port (the server)
```

The player-facing side is described under [Domains](/docs/stratosphere/features/domains).

### Quick install

On the machine that runs the panel (and that the A records will point to):

```bash
cd /var/www/pterodactyl
sudo php artisan p:router:install
```

`sudo bash tools/stratnet/install.sh router` does exactly the same thing. It installs the right binary for your CPU, creates the secret shared with the panel, runs the database migration, starts the service and opens the port in `ufw`. After that, users add an A record pointing at the machine and add the domain on a server's **Domains** tab.

Make sure nothing else on that machine uses port 25565. If one of your own servers uses it, give that server another port.

### Settings

Everything is in `/etc/stratosphere-net.env`. The router settings start with `ROUTER_`:

| Setting | Meaning |
|---|---|
| `ROUTER_PANEL_URL` | Where the panel is (`PANEL_URL` is used when this is not set). |
| `ROUTER_TOKEN` | The secret, it must match `PTERODACTYL_DOMAINS_ROUTER_TOKEN` in the panel's `.env`. |
| `ROUTER_LISTEN` | The port players connect to, `:25565` by default. |
| `ROUTER_REFRESH` | How often the list of domains is refreshed, `15s` by default. |
| `PROXY_PROTOCOL` | `1` sends a PROXY protocol v1 header to the backend, see below. |
| `*_MOTD` | The messages players see, see below. |

`PTERODACTYL_DOMAINS_TARGET_IP` in the panel's `.env` is the address users point their A records at; when it is empty, the panel's own address is used. If the router runs on another machine than the panel, set the token in the panel's `.env` (and `php artisan config:clear`), run `sudo bash tools/stratnet/install.sh router` there, and open port 25565 in the firewall.

### Player IPs and PROXY protocol

Players see the router's address on the backend. Set `PROXY_PROTOCOL=1` **only** for backends that understand it, for example Velocity with `haproxy-protocol = true`. Otherwise IP bans and IP logging see the router instead of the player.

### Messages while a server cannot be reached

The router asks the panel why, so the message a player sees is specific: the server is off, starting up, shutting down, suspended or still being installed. Suspended and installing servers are never connected to, and if the panel cannot be reached the player is simply told the server is off. Change the wording with `UNKNOWN_MOTD`, `OFFLINE_MOTD`, `STARTING_MOTD`, `STOPPING_MOTD`, `SUSPENDED_MOTD` and `INSTALLING_MOTD` (see `tools/stratnet/stratosphere-net.env.example`).

An extension can replace the wording per server: it adds a `notice` with a label and a message to the answer of `/api/router/state`, through the `router.state` hook, and the router shows that instead of its own wording. The sample Offline MOTD extension does this. Suspended and installing servers always keep the router's wording.

### Auto sleep

A server whose owner turned on [auto sleep](/docs/stratosphere/features/auto-sleep) is stopped by the panel when nobody has been on for a while. The router then shows "asleep, join to wake it up" in the server list, and when a player tries to **join** it asks the panel to start the server and tells the player to come back in a minute. Only joining wakes it (looking at the server list does not), and a server its owner stopped by hand is never started. Waking needs the server to have a domain on the router, because a stopped server has nothing else that could notice the player. Change the wording with `SLEEPING_MOTD` and `WAKING_MOTD`.

Java Edition only: Bedrock uses UDP and is not routed.

## The edge

The edge serves the panel over HTTPS with the certificates that were added in the panel under **Admin > Settings > Certificates**. PHP cannot do TLS by itself, the web server does, so the edge sits in front of the panel's web server:

```text
browser --https--> edge :443 --http--> nginx / Apache :80 --> panel
```

- It picks the certificate by the name the browser asks for (SNI): an exact name, a wildcard (`*.example.com` covers one label), or the **default** certificate (also for someone who used the IP address). A name that nothing covers, with no default, is refused.
- Install it once with:

  ```bash
  sudo bash tools/stratnet/install.sh edge
  ```

  It installs the program and the service, creates the secret (`PTERODACTYL_CERTIFICATES_TOKEN` in the panel's `.env`, `EDGE_TOKEN` in `/etc/stratosphere-net.env`), sets `TRUSTED_PROXIES` so the panel knows requests came over HTTPS, runs the migration and starts it. Then add a certificate in the panel. It is a separate secret from the router's, because it gives out private keys.

- Port 443 has to be free; a web server that already does HTTPS there must stop listening on it, or set `EDGE_LISTEN=:8443` and send port 443 to it some other way. The panel's web server keeps serving HTTP on port 80 (`BACKEND`).
- The edge settings are `EDGE_PANEL_URL` (or `PANEL_URL`; use `http://127.0.0.1` on the same machine or an https address, never plain http over a network), `EDGE_TOKEN`, `EDGE_LISTEN` (`:443`), `BACKEND` (`http://127.0.0.1:80`), `EDGE_REFRESH` (`60s`) and `HSTS_SECONDS` (`0`).
- With `HTTP_LISTEN=:80` it also answers on port 80: a name that has a certificate is sent to HTTPS (`301`, or `308` for requests that send something), anything else is passed on as before. The installer offers to move nginx to `127.0.0.1:8081` for this.

See [Certificates](/docs/stratosphere/admin/certificates) for the panel side of HTTPS.

## Which parts run

Each part is on when it has its secret, or you switch them in `/etc/stratosphere-net.env`:

```bash
ENABLE_ROUTER=1
ENABLE_EDGE=1
```

A part that cannot start (a port in use, no connection to the panel yet) is retried by itself, it does not stop the other one. `sudo bash tools/stratnet/install.sh` with no argument sets up both, `router` or `edge` only that part; running it again for the other part adds it and loses nothing. Logs: `sudo journalctl -u stratosphere-net -f`.

## Moving an older install

A machine that runs the old `mc-router` and `panel-edge` services is moved by `tools/stratnet/install.sh` or by the first router and edge update from **Admin > Updates**: the settings are copied into `/etc/stratosphere-net.env`, the old units are removed, and everything is rolled back if a step fails. An updater that was installed before this change cannot do it itself: after the panel update, press **Update router and edge** once more and the new updater moves it.

## Building and testing

The program is a Go module in `tools/stratnet` with the packages `router` and `edge` (Go 1.21 or newer).

```bash
cd tools/stratnet
go build
go test ./...
```

Building and packaging is wired into the panel release, and an admin can update the installed binary from **Admin > Updates**.
