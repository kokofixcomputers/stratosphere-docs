---
title: The admin area
description: How the admin area is part of the React app, and how to add a page to it.
---

The admin area used to be Blade pages (AdminLTE and jQuery) next to the React app. It is now drawn by the same React app as the rest of the panel, with the same components (cards, buttons, dialogs, inputs), the same sidebar style as the account pages and the same theme. The Blade layout, AdminLTE, jQuery and their assets are gone. `Admin\SpaController` answers every page of the admin area. The only things that are not pages are the downloads (`/admin/nests/egg/{egg}/export` and `/admin/servers/view/{server}/export`).

## How a page works

- **The page.** The `GET` route in `routes/admin.php` answers with `Admin\SpaController`, the same page as every other part of the panel. The permission middleware (`admin.can:...`) stays on the route, so the page is still refused for whoever may not open it.
- **The data.** `routes/api-admin.php`, mounted at `/api/client/admin` (it uses the session of the person, like the rest of the client API). Every route names its permission with `admin.can`, the same one as the page. The controllers are in `app/Http/Controllers/Api/Client/Admin` and use the same services as the Blade controllers did, so the rules (who may give which role, and so on) are the same code.
- **The app.** `routers/AdminRouter.tsx` has the sidebar, the small screen tabs and the routes. `routers/adminRoutes.ts` lists the pages and the permission each needs, and `lib/adminNav.ts` what the sidebar lists. The pages are in `components/admin/pages/*` and the calls in `api/admin/*`. What the signed in person may do (`admin_permissions`, every permission for root admins) comes with the page, see `User::toVueObject`.
- **Links.** Use `AdminLink` for a link to a page of the admin area.

## Adding a page

1. Write an API controller in `Api/Client/Admin` and its routes in `routes/api-admin.php`, each with its `admin.can`.
2. Write the React page in `components/admin/pages`, built from the existing components (`SettingsFrame`, `SectionCard`, `AdminTable`, and the fields in `components/admin/forms.tsx`), and add it to `ADMIN_ROUTES` and the navigation.
3. Answer the `GET` route of the page in `routes/admin.php` with `Admin\SpaController`.
4. Register the permission in `app/Services/Roles/PermissionRegistry.php` and the page in `app/Services/Roles/AdminNavigation.php` (a test fails when a route has no permission, or a permission is not used).
5. Write the tests. `tests/Integration/Admin` shows how.

<Callout type="warn" title="Two things that cost an afternoon">
  A route parameter called `{user}` or `{server}` in the client API is taken over by `SubstituteClientBindings`, so use another name (as `{person}` in the role members route). And in a PHPUnit process a request to the client API changes how later requests to Blade routes with `{user}` or a refused page are answered, so a test that does both should do the Blade request first.
</Callout>

## Trying it without a panel

`node preview/server.js` serves the app with an in-memory mock of the admin API, at `http://localhost:4000/admin`. Add the endpoints of a new page to `preview/server.js` to see it there.
