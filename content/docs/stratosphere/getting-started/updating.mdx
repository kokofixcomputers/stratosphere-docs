## Full update from the release archive

A full update uses the same steps as the [installation](/docs/stratosphere/getting-started/installation). Both archive types — the `nightly` build of every push and the release of every `v*` tag — contain the built frontend, so there is nothing to compile on your server. The archive replaces the panel's PHP files, the built interface and the shipped eggs; it contains no `.env`, so your configuration is kept.

Back up first — this is not optional — then extract and finish the update.

```bash
cd /var/www/pterodactyl
sudo php artisan down

# Back up first, this is not optional
sudo tar -czf ~/panel-backup-$(date +%F).tar.gz --exclude=vendor --exclude=node_modules .
sudo mysqldump panel > ~/panel-db-$(date +%F).sql   # use your database name

curl -L https://github.com/kokofixcomputers/StratPanel/releases/download/nightly/panel.tar.gz | sudo tar -xzv
sudo chmod -R 755 storage/* bootstrap/cache

sudo composer install --no-dev --optimize-autoloader
sudo php artisan view:clear
sudo php artisan config:clear
sudo php artisan route:clear
sudo php artisan migrate --seed --force

sudo chown -R www-data:www-data /var/www/pterodactyl/*   # nginx / apache user, use "nginx" on RHEL based systems
sudo php artisan queue:restart
sudo php artisan up
```

Hard refresh the browser afterwards (Ctrl+Shift+R). Swap the `nightly` URL for a release URL (for example `.../releases/download/v1.0.0/panel.tar.gz`) to install a fixed version.

## Update only the interface

`panel.tar.gz` replaces the whole panel. When all you want is the newest interface — the scripts and styles, the themes, the helper plugin jar and the Minecraft tools — every build also publishes a small `panel-ui.tar.gz`, and one command fetches it.

```bash
cd /var/www/pterodactyl
sudo php artisan p:update-ui --check               # is there something newer?
sudo php artisan p:update-ui                       # newest release
sudo php artisan p:update-ui --channel=nightly     # the build of the latest push
sudo php artisan p:update-ui --rollback            # the interface from before the last update
```

| Flag | What it does |
|---|---|
| `--check` | Reports whether a newer interface exists, without installing it |
| `--channel=nightly` | Follows every push instead of the newest `v*` release |
| `--rollback` | Puts back the interface from before the last update |

What it does: it asks the GitHub API for the newest build, downloads `panel-ui.tar.gz`, checks its size and the SHA-256 checksum GitHub lists, makes sure the archive only holds the interface folders, then swaps them into `public/` and keeps the previous ones in `storage/app/ui-backup` for `--rollback`. (On a release from before `panel-ui.tar.gz` existed it takes the interface folders out of `panel.tar.gz` and unpacks nothing else in it.) Run as root it gives the new files the owner of `public/`.

What it does not touch: PHP files, the database or `.env`. **A build that needs a migration still needs the full update above.**

The admin area also shows a notice with this command and a copy button when GitHub has a newer interface than the one installed. It looks at most every six hours, and only reads — it never installs anything by itself.

## Update every night automatically

Put this in the crontab of the web user to fetch the newest interface at 04:00 each night:

```text
0 4 * * * cd /var/www/pterodactyl && php artisan p:update-ui
```

Add `--channel=nightly` to follow every push. The `release` channel only has something once a `v*` tag was published. This stays a command on purpose rather than a button: replacing files needs the rights of whoever runs it, and a web request that can rewrite the panel's own files is not worth the risk.

## The Admin > Updates page

Root admins get an **Admin > Updates** page that can update the panel, the router and the edge from the panel itself. It downloads `panel.tar.gz` (latest release or nightly, your choice) and does what `tools/update-panel.sh` does, backing up the current files first. The page shows the maintenance screen for a minute or two and picks up the result by itself. See [Admin: Updates](/docs/stratosphere/admin/updates).

That page needs the one-time root service installed with `sudo bash tools/updater/install.sh`; without it, use the command-line update above.

<Callout type="info" title="Coming from Pterodactyl">
  There is no separate migration step. Extracting the Stratosphere archive over your Pterodactyl
  panel and running the commands above is the migration, and every later update uses the same flow.
</Callout>
